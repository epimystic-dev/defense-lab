# defense-lab research radar - 2026-10-25

The week's scan for what defenders actually need, and a short note on
what was built from it.

## Signal from the frontier

The scan prioritised two kinds of signal: (a) public hardening
standards that defenders already run against, and (b) recurring
observations of the gap between those standards and what shows up in
operator-saved configuration files. All sources are public standards
or public writeups; no live scans were performed.

1. **DMARC enforcement wave has not closed the posture gap.** The
   2024 Google / Yahoo bulk-sender rules required DMARC on
   high-volume senders, and the policy moved from "nice to have" to
   "mandatory for inbox delivery". Industry reporting through 2026
   continues to show that a large fraction of adopters set up DMARC
   with `p=none` (monitor-only) and never progressed to
   `p=quarantine` or `p=reject`. The posture gap has shifted from
   "no record" to "record exists but is non-enforcing".
   Why this matters: the posture lives in the operator's own zone
   file; a shape linter is enough to pin it.

2. **SPF 10-DNS-lookup cap is the quiet failure mode.** RFC 7208
   section 4.6.4 caps the lookup chain at ten `include` / `a` / `mx`
   / `ptr` / `exists` / `redirect` references; past ten, the receiver
   returns `PermError` and the message is treated as unauthenticated.
   Operators keep accreting `include:` entries for marketing /
   support / transactional / notifications senders without noticing
   the cap, and the record silently fails. Lintable at the file
   surface.

3. **DKIM selectors still ship with 1024-bit RSA keys.** NIST SP
   800-131A deprecated RSA below 2048 bits years ago, and M3AAWG BCP
   repeats the floor; many providers rotate to 2048 but leave the
   old 1024 selector live for backwards compatibility and never cull
   it. A linter that can decode the base64 p= tag and read the DER
   bit length catches this at the saved record.

4. **CIS Docker Benchmark 2026 revision reaffirms the fifteen-year-
   old root-first defaults.** Default-posture Dockerfiles still
   begin as root, use `:latest`, carry `ENV API_KEY=...` secrets,
   `curl | bash` installers, `chmod 777`, and `sudo` in `RUN`.
   docker-compose files add host-namespace sharing, `privileged:
   true`, docker-socket bind mounts, missing `cap_drop: - ALL`,
   missing resource limits. CIS section 4 (Image / Build) and
   section 5 (Container Runtime) are the stable citeable set.

5. **NIST SP 800-190 host-namespace isolation.** The guide names
   host network / pid / ipc namespace sharing as the specific
   container-isolation gaps the hardening posture must close. These
   map one-to-one onto `network_mode: host`, `pid: host`, `ipc:
   host` in compose - a lintable surface.

6. **OWASP Docker Top 10 D02: docker-socket bind-mount.** Mounting
   `/var/run/docker.sock` into a container confers root-equivalent
   host control to any process in that container. Still common in
   developer-oriented compose files for CI / monitoring / "I need to
   docker-run from a container".

7. **The ADD vs COPY choice remains a stable rulepack line.** CIS
   Docker Benchmark 4.9 names COPY as the simpler primitive; ADD is
   reserved for URL downloads and TAR extraction. A linter that
   flags ADD on a local file catches a documented smell.

### Belongs elsewhere

- Image-SBOM scanning / CVE matching against lockfiles: belongs in
  the sibling repro-lab or on the epimystic-lab axis. Not shape
  linting; defers to a different set of inputs.
- Running-container runtime policy enforcement (seccomp / AppArmor
  profile deltas against the running state): belongs with a runtime
  tool, not a static file linter.
- Agent-system guardrails for Dockerfile generation by AI tools:
  belongs in the agent-guard-lab.

### Deferred for later weeks

- `tlsconfcheck` (TLS parameters in nginx / Apache / HAProxy
  configs): still a strong candidate; needs three-dialect config
  parsing to be defensible; targeting a later week.
- `fwrules` (iptables / nftables shadowed and permissive rules):
  needs a parser that handles both ipt-save and nft-list output
  shapes; later week.
- `sbomdiff` (CycloneDX / SPDX completeness and release-to-release
  diff): valuable; needs careful boundary with the sibling labs that
  already handle developer-side artifact linting; later week.
- `secretage` (secret-rotation-age audit over metadata, never
  values): clean fit for the charter, needs well-shaped metadata
  input formats to be worth shipping; later week.

## What was built this week, and why

Two world-class artifacts, both pinned to standards defenders already
use.

- **`dnsrec`** - the saved zone file (or `dig` output) is the
  defender's one authoritative artifact for email-authentication
  posture, and the RFC 7208 / 7489 / 6376 / 8463 / NIST SP 800-177 /
  M3AAWG BCP controls that apply are a stable, cite-able set.
  Twenty-seven rules across SPF, DMARC, and DKIM. Every rule cites
  the public control it implements. The DKIM-004 RSA-bit-length
  rule carries a minimal ASN.1 BER walker so the key length is read
  directly from the published p= tag without any dependency.
  129 tests, zero dependencies, Python 3.9+.

- **`composecheck`** - the committed Dockerfile and
  docker-compose.yml are the developer's one authoritative artifact
  for container-image / container-service posture, and the CIS
  Docker Benchmark + NIST SP 800-190 + OWASP Docker Top 10 controls
  that apply are a stable, cite-able set. Twenty rules: ten image-
  build (DKF-prefix) and ten service-runtime (DC-prefix). A
  lightweight shape parser handles the compose YAML subset without a
  PyYAML dependency; the parser is deliberately conservative about
  `- key: value` sequence elements, treating them as scalars unless
  continuation lines prove them an inline mapping (the usual compose
  case: `- /var/run/docker.sock:/var/run/docker.sock` is a scalar,
  not a `/var/run/docker.sock -> /var/run/docker.sock` map).
  130 tests, zero dependencies, Python 3.9+.

Both tools are read-only against saved files; neither pulls an image,
builds a container, queries a DNS server, or sends mail. The reports
render every non-ASCII character as `<U+XXXX>` so a Windows cp1252
console cannot crash on them, and so a concealment character is made
visible in the report that is supposed to expose it.

A `tlsconfcheck` candidate was prepared and scoped during the plan
step but held back from this week's build: three-dialect config
parsing (nginx, Apache, HAProxy) is a build of its own, and
restraint-first ships two complete tools rather than one half-done
third.

## Honest note on scope

The scan was deliberately narrow this week - two focused tools, each
written and tested fully before shipping. The combined 259-test
suite exercises every rule on at least one shape fixture, round-trips
the text and JSON reporters, locks the `python -m <tool>` invocation
contract, and proves non-ASCII rendering under a cp1252 subprocess.
Future weeks will broaden the scan surface as the pipeline tooling
matures.
