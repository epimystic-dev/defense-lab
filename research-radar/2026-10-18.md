# defense-lab research radar - 2026-10-18

The week's scan for what defenders actually need, and a short note on
what was built from it.

## Signal from the frontier

The scan prioritised two kinds of signal: (a) public hardening
standards that defenders already run against, and (b) recurring
observations of the gap between those standards and what shows up in
operator-saved configuration and response files. All sources are
public standards or public writeups; no live scans were performed.

1. **CIS Linux Benchmark revisions through 2026 continue to flag
   default `sshd_config` as the primary posture gap on Linux hosts.**
   Section 5.2 (SSH Server Configuration) names fifteen directives
   whose default values leave the server reachable at
   brute-force-friendly settings: `PermitRootLogin`,
   `PasswordAuthentication`, `MaxAuthTries`, `LoginGraceTime`,
   `ClientAlive*`, `X11Forwarding`, `HostbasedAuthentication`,
   `IgnoreRhosts`, `UsePAM`. Operators keep hitting the same list.
   Why this matters: the posture lives in the operator's own saved
   `sshd_config`; a file-shape linter is enough to pin it.

2. **Mozilla's OpenSSH Guidelines remain the canonical modern
   `Ciphers` / `MACs` / `KexAlgorithms` allowlists** and the one
   defenders cite when challenged by compliance reviewers; distros
   continue to ship compile-time defaults that are a superset of the
   modern allowlist. The gap is pinnable at the file surface.

3. **OWASP Secure Headers Project baseline (HSTS, CSP,
   X-Content-Type-Options, Referrer-Policy, Permissions-Policy,
   X-Frame-Options or CSP frame-ancestors) remains the most
   frequently-missing surface on production HTTPS sites,** and the
   2026-vintage ASVS v4 revisions reaffirm the baseline. The
   cookie-attribute spec (RFC 6265bis) adds Secure / HttpOnly /
   SameSite as the hygiene set. Capturable with `curl -i`, pinnable
   at the file surface.

4. **CSP mis-adoption**: `unsafe-inline` and `unsafe-eval` continue
   to appear in production CSP headers, and `script-src *` or
   scheme-only wildcards collapse the policy to no mitigation. These
   are header-shape defects visible in the response the operator
   captured.

5. **Cookie-attribute gaps**: the Set-Cookie posture (Secure,
   HttpOnly, SameSite) is often set on login cookies but missing on
   the many other cookies a modern application emits. A linter
   reading the response reveals the full set.

6. **CORS specification contradiction** (`Access-Control-Allow-Origin:
   *` with `Access-Control-Allow-Credentials: true`) remains common
   enough that the Fetch Living Standard explicitly rejects the
   combination at the network layer. The server-side posture is
   still misconfigured.

## What was built this week, and why

Two world-class artifacts, both pinned to standards defenders already
use:

- **`sshdcheck`** - the saved `sshd_config` file is the operator's
  one authoritative artifact for SSH-server posture, and the CIS /
  Mozilla / NIST controls that apply are a stable, cite-able set.
  Fifteen rules, every rule cites the public control it implements.
  124 tests. Zero dependencies.

- **`headerscheck`** - the saved HTTP response (raw, headers-only, or
  HAR entry) is the capturable artifact for security-header posture,
  and the OWASP Secure Headers Project + RFC 6265bis + RFC 6797
  baseline is the cite-able set. Sixteen rules, every rule cites the
  public control it implements. 100 tests. Zero dependencies.

Both tools are read-only against a file the operator has already
saved; neither connects to any host, service, network, or person at
any point. The reports render every non-ASCII character as
`<U+XXXX>` so a Windows cp1252 console cannot crash on them, and so
a concealment character is made visible in the report that is
supposed to expose it.

A `tlsconfcheck` candidate was prepared and scoped during the plan
step but held back from this week's build to avoid a half-finished
artifact: the parser needs to handle three distinct config dialects
(nginx, Apache, HAProxy) to be defensible, and that is a build of
its own.

## Honest note on scope

The scan was deliberately narrow this week - a fresh lab, two
focused tools, written and tested fully before shipping. Future
weeks will broaden the scan surface as the pipeline tooling matures.
